# CIC Nexus

The `core/nexus` package is the central nervous system of the CIC Relay. It unifies the lifecycle of infrastructure state, from definition (IaC) to execution and audit recording.

## Modules

### 1. `iac` (Infrastructure as Code)
Responsible for loading the "Desired State".
- Supports multiple sources: Local File System (Git repo) and Upstream API.
- Builds the in-memory execution graph (`Relay` -> `Host` -> `Service`).

### 2. `recorder` (State Recorder)
Responsible for persisting the "Actual State" and "Expected State".
- Implements a local Git-based cache.
- Records every transaction snapshot for debugging and audit.

### 3. `crypto` (Security & Signing)
Responsible for the cryptographic integrity of the audit trail.
- Integrates with HashiCorp Vault Transit engine.
- Signs Git commits generated by the `recorder`.

### 4. `sync` (Audit Synchronization)
Responsible for long-term audit storage.
- Squashes daily local cache into a single audit commit.
- Pushes the audit trail to the central repository.

### 5. `isolation` (Process Isolation)
Responsible for the "Zero Trust" execution model.
- Manages separate processes for Host, Relay, and Module identities.
- Handles secure IPC for the 3-step decryption chain.

### 6. `operator` (GitOps Lifecycle)
Responsible for dynamic onboarding/offboarding.
- Watches the Infrastructure Repo.
- Manages bootstrap tokens and certificate lifecycles.

### 7. `types`
Common type definitions shared across the Nexus modules.
